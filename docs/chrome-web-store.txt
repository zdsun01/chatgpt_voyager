详细说明
----------
ChatGPT Voyager 让 ChatGPT 长对话更好读。

• 返回原文：使用网页自带的“向 ChatGPT 提问”引用追问后，点击新回答底部的 ↩ 回到来源段落。
• 侧边临时聊天（试用）：从聊天更多菜单打开独立的官方临时聊天，不复制主对话上下文；点击 × 关闭，再打开从空白开始。
• 时间线：悬停右侧圆点预览自己的提问，点击跳转，随阅读位置高亮节点。

支持 chatgpt.com 和 chat.openai.com，需要可正常使用 ChatGPT 的账号。返回关系保存在浏览器本地。侧边聊天发送内容由 ChatGPT 官方服务处理；打开期间会额外运行一个网页。

本扩展是独立项目，与 OpenAI 无隶属或官方背书关系。

单一用途
----------
为 ChatGPT 网页提供对话阅读辅助，帮助用户在长对话中定位提问、返回引用原文，并在不离开阅读页面的情况下开启独立临时追问。

权限理由
----------
storage：在浏览器本地按聊天保存返回关系，包括消息标识、最多 240 字符原文定位片段和位置数值，以便刷新后恢复。不上报给开发者，不使用 storage.sync。
站点访问：只在 https://chatgpt.com/* 和 https://chat.openai.com/* 注入界面及监听必要交互，以识别当前消息、显示时间线和返回箭头、打开临时侧边网页。

远程内容说明（提交时必须披露）
----------
所有扩展逻辑都打包在 ZIP 内，没有远程脚本下载、eval 或远程配置执行。
side-chat.js 在用户点击打开时嵌入当前 ChatGPT 站点的 /?temporary-chat=true 页面。该远程网页运行其自己的官方脚本，不获得扩展 API 权限；不提供 MAIN-world 桥接或 externally_connectable 接口。
父 content script 访问同源 iframe 的 DOM，确认临时模式、调整导航界面并处理关闭。应向审核人员披露此远程 iframe，不应笼统声明完全没有远程内容。最终勾选以后台问题的实际措辞及审核规则为准。

用户数据申报依据
----------
本地处理：网站内容（提问、引用片段）、消息/聊天标识与交互定位信息。浏览器本地持久化少量返回定位数据。
外部处理：用户主动使用嵌入的 ChatGPT 页面时，其输入交由 OpenAI；开发者不接收聊天内容或账号凭据。
不要把“开发者不接收数据”写成“扩展不处理任何数据”。按后台对收集/处理的具体定义填写，保持与 PRIVACY.md 一致。

审核测试步骤
----------
1. 登录 ChatGPT，进入含多次提问的聊天，悬停和点击右侧节点。
2. 选中模型回答文字，用官方引用提问入口发送追问；新回答出现后检查 ↩ 并点击返回。
3. 刷新后检查已记录的返回关系恢复。
4. 聊天更多菜单 → 新建侧边聊天，或 Ctrl + Alt + S；确认独立临时聊天可显示与发送，点击 × 关闭后重开应为空白。
5. 侧边聊天目前标为试用。已有用户截图确认内嵌官方页面显示；完整发送、关闭与重开的实网页流程仍待补充验证。
